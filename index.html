Read before integrating

Critical facts hidden by a generic payload example.

These are current implementation facts. They are deliberately separate from any desired future protocol rules or third-party indexer behavior.

Mint hashes are server-generated. POST /block20/order fetches the current tip hash for every normal mint and emits it as hash. A client does not supply the hash in this endpoint.
Always provide a valid user-controlled receiver address. An omitted or empty receiverAddress makes reveal fall back to the generated commit address. That address is controlled by server-held key material, and it is not returned as a destination field in later order reads.
Do not infer stricter token rules from the current writer. The public order endpoint accepts zero and decimal amounts, and it does not validate ticker syntax or deployment max/lim values. Compatibility depends on the consuming indexer.
Keep the evidence that matters. Retain the order ID, exact inscriptionJson, selected receiver address, commit transaction, reveal transaction, network, and the indexer used to evaluate the result.

Integration path

From request to verifiable inscription.

The operational stages are as important as the JSON fields. Treat the order response as a payment instruction, not as proof that a token has been accepted by an indexer.

Create an order

Submit an API request with the action, ticker, fee rate, and an explicit receiver address. Record the returned payload and payment details before showing a payment action.

Fund the commit address

Send an intentional payment to the returned commitAddress, using the returned commitAmount as the minimum required output value. Do not mix unrelated funds into that address.

Allow or trigger reveal

The monitor checks eligible UTXOs and attempts a reveal. An advanced API caller can also submit a commit outpoint to the reveal endpoint, but that endpoint is not an authorization proof.

Verify on chain and in the target reader

Confirm the reveal transaction contains the expected bytes, then query the same compatible indexer or reader that will display or settle the result.

Scope and authority

Accurate by design, not a universal consensus claim.

This documentation describes the behavior of the Bitcoin Universe Inscribe implementation. It does not define network-wide token consensus, an authentication policy, wallet custody guarantees, or a required interpretation for every BLOCK-20 reader.
