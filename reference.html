Payload specification

What the Inscribe writer actually inscribes.

A precise description of the compact JSON emitted by the current Bitcoin Universe Inscribe BLOCK-20 writer, including the distinction between an API input and the on-chain object.

Encoding
Compact JSON.stringify output, encoded as UTF-8.
Envelope
Ordinals ord envelope, with content type text/plain;charset=utf-8.
Reader contract
Payload syntax alone does not determine balances, ordering, validity, or settlement.
Implementation profile, not universal consensus. This page specifies what the reviewed InScribe writer emits. It does not claim that every independent BLOCK-20 indexer accepts these messages, assigns the same state, or applies the same validation rules.

Wire format

One JSON object, carried by an inscription.

The REST body is a construction request. The on-chain content is the returned inscriptionJson field. Parse the resulting JSON object rather than expecting a client-supplied body to be preserved unchanged.

Payload bytesCurrent writer
UTF-8 encoded JSON.stringify(payload)
Inscription content typeCurrent writer
text/plain;charset=utf-8

The standard inscription envelope includes ord; neither a protocol MIME type nor an OP_RETURN output is used by this writer.

Field ledger

Field meaning and current writer behavior.

Required means required in the emitted operation shape. The second half of this page describes the separate REST-level checks, defaults, and omissions.

FieldOperationsEmitted formMeaning in this writer
pAllString, always block-20Injected by the server. API callers do not provide it.
opAllStringCopied from API action. The writer recognizes exactly deploy, mint, and transfer.
tickAllStringCopied from API input without normalization. The API requires a nonblank string, but does not apply a length, character, or case rule.
maxDeployStringCopied from maxSupply through string coercion, or defaults to "21000000" when omitted.
limDeployStringCopied from limitMint through string coercion. In the public order path, when omitted it uses normalized amount, which defaults to "0".
desDeployString, optionalCopied only when API description is truthy. The server does not validate its contents.
amtMint, transferStringSerialized from normalized API amount. The current endpoint permits finite values from 0 through JavaScript safe integer range, including decimals.
hashMintStringFetched from the configured Bitcoin tip source and injected by the server. It is not a public order input. The writer trims it but does not locally verify a 64-character hex shape.

Input to output mapping

The REST request is not the payload.

These transformations are crucial for client-side previews and audit records. The order response is the authoritative record of the payload the server attempted to inscribe.

Validation boundary

What the current API checks, and what it does not.

Keep this boundary visible in any UI. Stronger validation may be sensible for your product, but it is not currently an enforcement property of the documented server endpoint.

Checked by the order endpoint

  • The body must be a JSON object.
  • action and tick must be nonblank strings.
  • action must ultimately resolve to one of the three supported operations.
  • feeRate is a finite number or numeric string from 1 to 10,000, default 5.
  • amount is finite and between 0 and Number.MAX_SAFE_INTEGER, default 0.
  • repeatCount is from 1 to 100 and is floored, default 1.
  • outputValue below 330 sats becomes 0; values at or above 330 are floored.

Not enforced by the order endpoint

  • Ticker format, case, maximum length, or uniqueness.
  • Integer-only or positive-only amount semantics.
  • Numeric formatting or supply relationships for maxSupply and limitMint.
  • Description size or contents.
  • A valid user-controlled receiver address at order creation time.
  • A 64-character hex shape for the upstream mint hash before it is emitted.
