The inscription

Small payloads with a clear purpose.

BLOCK-20 writes compact UTF-8 JSON inside a Bitcoin inscription. The operation tells a compatible reader whether the message defines a ticker, mints an amount, or prepares a transfer.

Protocol marker
block-20
Actions
Deploy, mint, transfer
Carrier
Bitcoin inscription
Reader choice matters. Bitcoin proves the inscription bytes and transaction history. A compatible BLOCK-20 reader interprets token validity, balances, ordering, and state. Check the reader you trust before relying on an outcome.

Three actions

Read the preview before payment.

The order page shows the exact compact payload. The examples below explain the fields without representing a real ticker or transaction.

DeployDefines a ticker
{
  "p": "block-20",
  "op": "deploy",
  "tick": "BLK",
  "max": "21000000",
  "lim": "1000",
  "des": "Optional description"
}
MintCreates an amount
{
  "p": "block-20",
  "op": "mint",
  "tick": "BLK",
  "amt": "1000",
  "hash": "<bitcoin-block-hash>"
}
TransferPrepares movement
{
  "p": "block-20",
  "op": "transfer",
  "tick": "BLK",
  "amt": "250"
}

Field guide

What each short name means.

Compact names keep the inscription small. Their values remain readable in your order preview.

FieldMeaningWhere it appears
pThe BLOCK-20 protocol marker.Every action
opThe action: deploy, mint, or transfer.Every action
tickThe ticker exactly as shown in the order.Every action
maxThe intended maximum supply.Deploy
limThe intended amount allowed per mint.Deploy
desAn optional public description.Deploy
amtThe amount represented as text.Mint and transfer
hashThe Bitcoin block reference captured when a mint order is created.Mint
Exact values matter. Ticker spelling, capitalization, amounts, supply, limits, descriptions, and the mint hash become part of the inscription. If anything is wrong before payment, discard the order and create a fresh one.
