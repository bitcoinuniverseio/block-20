Mint hash

A Bitcoin block reference captured for your mint.

When a BLOCK-20 mint order is created, its payload includes the Bitcoin tip block hash observed at that moment. The value becomes part of the exact inscription you review.

Captured
When the order is created
Stored
Inside the mint payload
Not the same as
The later reveal transaction or block

Why it is there

The mint records a point in Bitcoin history.

The block hash gives the mint inscription a specific reference chosen before payment and reveal. It is not chosen by the wallet, and it should match the hash shown both in the order details and inside the payload.

1

Order begins

Universe Inscribe observes the current Bitcoin tip while preparing the mint.

2

Hash is embedded

The observed 64-character block ID is placed in the payload's hash field.

3

Reveal comes later

Funding and reveal happen afterward; they do not replace the saved mint hash.

Review it

One value, shown in two places.

Before payment, compare the order's block hash with the hash inside the displayed mint payload. They should be exactly the same lowercase text.

Mint payload shapeExample only
{
  "p": "block-20",
  "op": "mint",
  "tick": "BLK",
  "amt": "1000",
  "hash": "<64-character-bitcoin-block-hash>"
}
Do not edit a mint hash. Changing the hash changes the inscription. If the value is missing, malformed, surprising, or does not match the order details, do not pay. Create a fresh order.

After reveal

Verify the inscription you received.

Open the reveal transaction, inspect the inscription payload, and compare its hash, ticker, and amount with the order you saved. A compatible reader may also apply its own rules about block history and token state.

A block hash is not a promise of mint success. It records what was observed when the order was created. The compatible reader you choose determines how that inscription affects BLOCK-20 state.
